# ADR-002 订单与状态日志使用逻辑关联

状态：已确认。

## 背景

`orders` 保存订单当前数据，`order_status_log` 保存状态变化。两张表都由同一单体应用写入，业务侧需要确保每条日志对应有效订单，且日志与已提交的状态一致。

## 决策

使用 `order_status_log.order_id` 逻辑关联 `orders.id`，并为 `(order_id, created_at)` 建索引。MySQL 不声明物理外键或级联动作。两表使用 InnoDB，由应用显式控制校验和写入。

该决策将订单存在性、删除策略和状态变更顺序集中在 Service 的业务入口，数据库保留字段、索引和单行取值约束。代价是绕过 Service 直接写表时，数据库无法阻止孤儿日志或核对订单与日志是否对应，因此受控写入口和事务测试是必要的。

## 一致性方案

1. Service 在写入状态日志前确认关联订单存在，并验证这次变更符合状态规则。日志引用服务端确认的订单 ID。
2. 订单状态更新与日志插入在同一个 MySQL 事务内完成。只有状态更新成功才写日志，任一步失败则回滚事务。
3. 订单业务不提供物理删除入口。若发现绕过应用写入造成数据不一致，先核对实际数据与对应业务操作，再决定修复方案。

本 ADR 记录应用层方案，事务与并发控制的实现和测试按项目阶段推进。
